HTTP API: convert, generate, diagnose, discover
Overview Web tools Building messages AI assistants (MCP) API reference

Base URL: https://v2x.tools. Plain HTTP, no authentication for the public message set. A bearer token from your asn1click account adds your own defaults and modules.

Concepts

Encodings

  • UPER / WER: binary, sent and received as hex text (optional uper: / wer: prefix).
  • JER / XER: JSON (X.697) and XML (X.693). Every encoding checks the constraints.

Identifying the message (X-Ref)

  • Auto-detect: omit X-Ref. The ETSI ITS header (protocolVersion + messageID) picks the message: the public default (newest version), or your own default when signed in.
  • Message: X-Ref: _cam_v2_3, a pre-configured message (header values set when generating). See Discover.
  • Type: X-Ref: _cam_v2_3:CAM (moduleId:Type), a raw ASN.1 type, no header defaults.

Encoding rules (X-Compat)

Optional on convert, generate and diagnose: standard (default, X.691) or asn1c, which encodes like asn1c-based stacks such as Vanetza.

Which definition was used

Responses carry X-Resolved-Ref (e.g. _cam_v2_3:CAM), X-Resolved-Message (_cam_v2_3), X-Auto-Detected (true/false) and X-Compat.

Convert

POST /api/convert

Decode, encode or re-encode a payload. The body is the payload.

HeaderRequiredDescription
X-FromrequiredInput: UPER, WER, JER or XER.
X-TorequiredOutput: same values.
X-RefoptionalWhich definition; omit to auto-detect.
X-Compatoptionalstandard or asn1c.

Decode UPER to JSON (auto-detect)

curl -X POST "https://v2x.tools/api/convert" \
  -H "X-From: UPER" -H "X-To: JER" \
  --data "uper:0202000004d200000059ca02160d929e71000000000030d40000000002b6800000028003ff01fff800"

# → {"header":{"protocolVersion":2,"messageId":2,"stationId":1234},"cam":{...}}

Encode JSON to UPER (explicit message)

curl -X POST "https://v2x.tools/api/convert" \
  -H "X-Ref: _cam_v2_3" -H "X-From: JER" -H "X-To: UPER" \
  --data @cam.json

Generate

POST /api/generate

A sample message. X-Ref (required) names the message; JSON body, all optional:

FieldDescription
formatUPER (default), WER, JER or XER.
contentMINIMAL (default), RANDOM or FULL.
overrides[{"path": "…", "value": "…"}]: fields to set. Syntax in Building messages.
Since 2026-11-24 content replaces size and minimal; without it the sample is MINIMAL (it used to be a small random one).
curl -X POST "https://v2x.tools/api/generate" \
  -H "X-Ref: _cam_v2_3" -H "Content-Type: application/json" \
  --data '{"format":"UPER","content":"RANDOM"}'

Diagnose

POST /api/diagnose

Bit-by-bit breakdown of a UPER payload (X-From: UPER; X-Ref optional). For every field: its bits, raw value, decoded value and type, plus the structural bits (extension markers, presence bits, CHOICE indexes, lengths). A broken payload still answers 200 with what was decoded up to the failure, the field being read and the bit where it broke (error, failurePath, failureBit). Values outside their declared range are flagged in constraintViolations.

curl -X POST "https://v2x.tools/api/diagnose" -H "X-From: UPER" --data "uper:0202…"

# → {"payloadBits":344,"decodedBits":344,"paddingBits":0,"constraintViolations":0,
#    "entries":[{"start":8,"end":16,"path":"CAM.header.messageId","kind":"VALUE","bits":"00000010",
#                "value":"2","type":"MessageId (0..255)"}, ...], "decoded":{...}}

Discover

GET /api/messages

The pre-configured messages; each name is a valid X-Ref.

curl "https://v2x.tools/api/messages"

# → [{"name":"_cam_v2","moduleAlias":"_cam_v2","rootElement":"CAM","description":"CAM v2",
#     "options":{"fixups":[{"path":"header.protocolVersion","value":2},{"path":"header.messageID","value":2}]}}, ...]

GET /api/messages/versions

Per header identity (protocolVersion:messageID, e.g. 2:1 = DENM): the available versions, the public default and the one used for you (effective).

GET /api/modules

The ASN.1 modules: moduleId (use it in moduleId:Type refs), oid, a one-line description and the number of types. Optional sort=name (default) or sort=uploaded.

curl "https://v2x.tools/api/modules"

# → [{"moduleId":"_cam_v2_3","oid":"CAM-PDU-Descriptions {itu-t(0) identified-organization(4) ...}",
#     "short":"Cooperative Awareness Message (CAM) ...","elementCount":...}, ...]

GET /api/index/elements?moduleId=…

The types of a module with their kind, fields, constraints, named values and ASN.1 comments.

Errors & status codes

  • 200: success; the body is the converted or generated payload (or the requested data).
  • 400: the payload could not be decoded or encoded, or a value breaks its constraints; body {"error": "…"} naming the field.
  • 404: unknown ref, or auto-detect found no message for the payload's header.
